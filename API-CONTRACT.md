# Search Pals API contract

All endpoints use same-origin cookies and return `{error: string}` with an HTTP error status on failure. Responses are JSON except the public pet photo endpoint. Times are Unix milliseconds. Shared types are in app/types.ts. Unsafe requests require `Content-Type: application/json` and same origin. Successful mutation responses can be small `{ok: true}` unless specified; clients reload room state afterward. The production deployment target is PHP 8.1+ with PDO SQLite on cPanel; the earlier TypeScript/D1 handler is a reference implementation and does not include the later API additions below.

- `GET /api/session` -> SessionResponse (anonymous permitted)
- `POST /api/session` body `{name, avatar?: JPEG data URL|null, termsAccepted?:true, adultConfirmed?:true, termsVersion?:'2026-11-14'}` -> SessionResponse, creates or updates a device guest profile and HttpOnly cookie. All three acknowledgement fields are mandatory for a new profile; the service records their timestamp/version. Existing profile edits need not repeat acknowledgement. This records an adult declaration, not identity or age verification. Updating a profile preserves member identity/roles.
- `GET /api/privacy/export` -> complete downloadable JSON, streamed without accumulating all rows in PHP memory. Requires the current device profile cookie. Fields: `exportedAt`, `profile` (including acknowledgement record, excluding credentials), `memberships`, `ownedSearches`, `messages`, `mapReports`, `abuseReportsSubmitted`. Contains only this profile's submitted content and own memberships/appeals, not other participants' contributions or private staff reports about the requester. Includes a `Content-Disposition: attachment` header. Limited to six exports per minute.
- `POST /api/privacy/delete` body `{confirm:'DELETE MY DATA', deleteOwnedSearches?:boolean}` -> `{ok:true,ownedSearchesDeleted:number}`. Requires the current device profile cookie and same-origin JSON. If any search is organised by this profile, `deleteOwnedSearches:true` is required; otherwise returns 409 before deleting anything. Deletes the profile, its authentication token, memberships and own contributions; explicitly acknowledged owned rooms and all their contents are also deleted. Unrelated rooms/contributions remain. Clears the guest cookie. Authenticated deletion is exempt from ordinary write quotas. No client-supplied guest ID is accepted.
- `POST /api/searches` body CreateSearchInput -> `{code}` (requires profile; creates approved organiser membership)
- `GET /api/searches/:code` -> Room. Nonmembers/pending/banned receive public appeal only, no messages, member list, precise helper locations, or reports. `me` remains available so client can display status.
- `GET /api/searches/:code/photo` -> public JPEG with `Content-Type: image/jpeg`, `X-Content-Type-Options: nosniff` and cache headers, or 404 when absent. `Search.photo` in rooms and session summaries is this same-origin URL or null, avoiding a base64 photo in each poll.
- `POST /api/searches/:code/join` body `{}` -> `{ok:true}` (pending by default, existing membership idempotent; bans enforced)
- `PATCH /api/searches/:code` body `{joinPaused?: boolean, status?: 'active'|'found'}` organiser only; found clears shared locations and disables writes except moderation
- `POST /api/searches/:code/messages` body `{content, kind:'chat'|'update'}` approved members only; updates organiser/moderator only
- `DELETE /api/searches/:code/messages/:id` body `{}` author or organiser/moderator; no cross-search deletions
- `POST /api/searches/:code/reports` body `{kind:'sighting'|'searched'|'searching',lat,lng,radius,note,occurredAt}` approved members only
- `PATCH /api/searches/:code/reports/:id` body `{confirmed:boolean}` organiser/moderator; only sighting reports
- `DELETE /api/searches/:code/reports/:id` body `{}` author or organiser/moderator; no cross-search deletions; permitted after closure for moderation, like message deletion
- `POST /api/searches/:code/location` body `{lat,lng,accuracy,version}` or `{stop:true}` approved members only. `version` must be a nonnegative integer equal to the member's persisted location version, otherwise 409. `Room.me.locationVersion` provides the current version (initially 0); other member DTOs need not expose it. Stop atomically clears the coordinates and increments the version, preventing an older GPS callback from restarting sharing. Fetch the latest room before starting a new sharing session. Coordinates also clear on ban/closure, and regular updates require an active search.
- `PATCH /api/searches/:code/members/:id` body `{status?:'approved'|'banned',role?:'helper'|'moderator',removeAvatar?:true}`. :id is guest id. Organiser/moderator may approve/remove helpers; only organiser changes roles; cannot act on organiser or self, moderators cannot act on other moderators.
- `POST /api/searches/:code/abuse` body `{targetType:'message'|'member',targetId,reason}` approved members only, scoped targets
- `PATCH /api/searches/:code/abuse/:id` body `{resolved:true}` organiser/moderator

GET room returns maximum 150 recent messages, 200 map reports and only unresolved abuse reports. No unbounded arrays. Live message `authorAvatar` is null; clients look up the author's avatar in `Room.members`, so each photo is transmitted once instead of repeated for every message. Current shared positions expire after 30 minutes and must show freshness; poll room every 5 seconds only while visible. Joining/profile/create/write endpoints rate limited persistently. No automatic sample records in live database. Demo mode is entirely local, clearly labelled, and uses the same UI types.

## Retention and maintenance

The SQLite schema is version 2. Migration adds acknowledgement timestamps and search `closed_at`/`activity_at`; existing profiles are not falsely marked as accepting new terms. Completed legacy searches without a recorded closure date receive the migration timestamp, giving them a full 90-day retention period.

Completed searches become eligible for deletion 90 days after their first closure. Active searches become eligible after 180 days without a successful approved-participant write (including GPS updates, chat, reports and management actions). Reading/polling, profile edits and pending join requests do not extend a search's retention. Closing a completed search again does not reset its closure date. Cleanup deletes the search and all associated memberships, messages, map reports, moderation reports and duplicate fingerprints.

Each normal API request runs bounded cleanup inside the database transaction: up to 20 eligible searches, 500 expired location rows, 500 expired security counters, 500 old duplicate fingerprints and 100 expired unreferenced profiles. GPS is always hidden from room responses after 30 minutes, even if cleanup has a backlog. Guest cookies and server sessions expire after 180 days; a profile record remains while retained memberships/contributions/moderation references still need attribution, and becomes eligible for removal once expired and unreferenced. Security counters become eligible 24 hours after their limit window expires; duplicate-message fingerprints become eligible after two minutes.

`server/maintenance.php` is CLI-only and runs the same cleanup with a search batch limit of 100. `php server/maintenance.php --dry-run` reports eligibility without deleting records, but opening the database can initialise or migrate its schema. Configure the correct private `SEARCHPARTY_DATA_DIR` explicitly when scheduling the hosting account's PHP CLI. Run daily to process eligible data even when the website is idle. A bounded batch/backlog or absent cron can delay removal until subsequent cleanup; retention is not an exact-clock guarantee. Hosting access logs, database backups and copies downloaded/shared by users are outside this application's cleanup.
